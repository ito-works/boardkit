# boardkit

boardkit is a curses-free TUI engine for terminal boards: cell-width aware text
clipping and wrapping (`text`), 256/8-colour style tables (`styles`), tiered
layout with viewport scrolling (`layout`), pure key handling and overlay state
(`cursor`), background workers and coalescing (`workers`), background expansion
fetches (`expand`), the curses loop and the Board protocol (`app`), and
`windows`, `context` and `launcher` on top of them. It imports `curses` nowhere
at module level, so everything but the loop is testable without a terminal, and
it is stdlib only: there is nothing to install.

## Status: work in progress

**This repository is a read-only MIRROR.** Its tree is published from
`ops/repoman/boardkit` in a private fleet repository, after each landing there,
by a job (`boardkit-publish`), out of the commit named in `SOURCE`. `boardkit/`
holds that commit's top-level `.py` sources verbatim (a subpackage in the
source, such as `contexts/`, is integration code for the private board and is
not published); `README.md`, `LICENSE`, `VERSION`
and `SOURCE` are generated by the job, and every other path at this root is
removed on the next run.

What that means if you are reading this from outside:

- **The API and the module layout may change without notice.** This is
  published work in progress, not a released library. Pin `VERSION` and expect
  a module, a function or a signature to move between versions.
- **Issues and pull requests here are not watched.** Nothing here is edited by
  hand, and a commit made here directly is discarded by the next publish.
  Changes happen upstream.
- **It exists so the fleet's own consumers can import one engine without a
  credential.** Two terminal boards are built on it, and their CI is hermetic
  and holds no secret, so a public mirror is the thing that lets them share an
  engine rather than each vendoring a copy. That is the whole of its current
  purpose.
- **It may become the source of truth later**, alongside the fleet's landing
  tooling ("mujin") if that is published too. Until then, upstream is.

## Using it

Put this checkout's directory on `sys.path` and import the package:

```python
import sys
sys.path.insert(0, "/path/to/boardkit-checkout")

import boardkit
from boardkit import text, layout, cursor

PINNED = "..."          # this checkout's VERSION, copied into your code
if boardkit.__version__ != PINNED:
    raise SystemExit("boardkit moved: pinned %s, found %s"
                     % (PINNED, boardkit.__version__))
```

The package is pure Python and needs nothing beyond the standard library.

`VERSION` holds `boardkit.__version__`, the string to pin against. `SOURCE`
holds the upstream commit this tree was published from. It is provenance, not a
link: the repository it names is private.
